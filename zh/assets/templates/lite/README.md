# 项目文档中心（简化版 Lite）

> 适用于小型单体项目、工具库或独立微服务。保留动静分离与 4 态变更包机制，剔除重型冗余目录。

## 目录结构

```text
doc/
├── .godkey.json            # 文档体系配置（profile: lite）
├── 01-项目说明.md          # 静态快照：产品定位、快速启动、环境与部署
├── 02-架构与设计.md        # 静态快照：分层架构、模块功能蓝图、数据库表结构快照
├── 03-开发规范.md          # 静态快照：项目专属代码与 Git 规范
└── 04-迭代变更/            # 动态工作区：按功能组织、文件夹即状态
    ├── 01-待确认/          # 方案待评审
    ├── 02-进行中/          # 正在开发迭代的功能包
    ├── 03-已搁置/          # 中途暂停或中止的实验包
    ├── 99-已归档/          # 已完成且同步静态文档的历史包
    └── hotfix记录.md       # 单文件小修结构化台账
```

## 核心规则

1. **动静分离**：`01~03` 永远只写“系统当前是什么样”；开发过程方案、进展、测试、审查、迁移 SQL、一次性脚本全部放进 `04-迭代变更/` 的对应功能包。
2. **目录即状态**：通过脚本流转文件夹位置表示状态，不在正文手改“进行中/已完成”。
3. **归档门禁**：功能完成后，必须先同步更新 `01~02` 静态快照文档，再通过 `godkey_gate.py archive` 校验并迁入 `99-已归档/`。

## 升级到完整版（Full）

当项目出现多个业务模块、多张数据表或独立部署链路时，可将静态单文件平滑拆分为完整版 `01~08` 目录，并把 `04-迭代变更/` 重命名为 `09-迭代变更/`，同时将 `.godkey.json` 整体替换为完整版配置（同步更新 `profile`、`changesDir` 与 `staticSyncRules`）。
