# 项目文档中心（完整版 Full）

> 适用于中大型项目、多模块服务与长期迭代业务系统。核心设计：**静态快照与动态变更彻底分离**。

## 目录结构

```text
doc/（多模块项目可用 {project_name}_doc/）
├── .godkey.json              # 文档体系配置（profile: full）
│
├── 【静态层：项目当前唯一真相（快照）】
├── 01-产品介绍/              # 产品定位、核心特性、快速开始
├── 02-使用指南/              # 用户操作手册
├── 03-系统架构/              # 分层架构、模块边界、技术选型
├── 04-功能设计/              # 各模块当前生效的功能蓝图（核心）
├── 05-数据库/                # 当前最新完整表结构快照（DDL + 说明）
├── 06-开发规范/              # 代码规范、Git 规范、框架关键约束
├── 07-部署运维/              # 环境配置清单、标准部署与回滚手册
├── 08-资源文件/              # Swagger 导出、架构图、原型与截图
│
└── 【动态层：按功能驱动的迭代工作区（文件夹即状态）】
    └── 09-迭代变更/
        ├── 01-待确认/        # 方案待评审
        ├── 02-进行中/        # 正在开发迭代的功能包（含方案/进展/测试/审查/ops）
        ├── 03-已搁置/        # 暂停或中止的实验包
        ├── 99-已归档/        # 已完成且通过静态同步门禁的历史功能包
        └── hotfix记录.md     # 单文件小修结构化台账
```

## 维护铁律

1. **静态层只留最新真相**：直接更新为系统当前状态，不靠“只追加不删旧内容”堆出僵尸文档。
2. **动态资产归入功能包**：迭代方案、跨会话进展、测试计划与报告、代码审查、迁移 SQL、一次性数据脚本、临时上线配置统一归入 `09-迭代变更/<状态>/<日期_功能名>/`。
3. **数据库只存快照**：`05-数据库/` 维护当前完整表结构快照；开发期迁移 SQL 与一次性订正脚本放在功能包的 `ops/`，上线归档时更新快照并随包归档留痕。
4. **先同步再归档**：任何功能包从 `02-进行中/` 迁入 `99-已归档/` 前，必须同步静态层并跑通 `godkey_gate.py archive` 校验。
