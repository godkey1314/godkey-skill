# eval-1：新功能开发（标准全链路）

## 前置条件

- 一个已用 `godkey_gate.py init --profile full` 初始化并纳入 Git 管理的代码项目；
- 项目至少包含接口层 / 业务层 / 数据层，具备可新增的跨文件功能点（如“用户列表导出 Excel”）。

## 用户指令

> 帮我加一个用户数据导出 Excel 的功能

## 期望行为检查表

- [ ] 第一步运行 `godkey_gate.py audit`，确认 `full` 模式与活跃功能包状态
- [ ] 读取了 `references/开发流程.md` 全文再开始执行
- [ ] **Pass 0**：先读 `06-开发规范/`、`03-系统架构/`、`04-功能设计/` 及依赖声明文件，输出可逐条对照的规范/框架约束清单
- [ ] **Pass 1**：先只读源码摸底，输出四类文件清单（直接改动 / 上游调用方 / 下游依赖与基类 / 范式参考与已排除），判定走标准功能包
- [ ] **Pass 2**：通过 `godkey_gate.py new` 在 `01-待确认/` 或 `02-进行中/` 建包，将 `01-方案.md` 与分层改动清单落盘后再改业务代码
- [ ] **Pass 3 & 4**：精准施工、清理废代码，将自检/审查结果与测试计划/报告分别落盘至 `04-审查.md` 与 `03-测试.md`，并更新 `02-进展.md`
- [ ] **Pass 5**：同步更新 `04-功能设计/` 等静态真相快照，实际运行 `godkey_gate.py archive` 并向用户贴出 `ARCHIVE PASS` 输出

## 反例警报（出现即不通过）

- ❌ 未读 `references/开发流程.md` 就直接改代码
- ❌ 没读源码就编造方案里的文件名与函数名，或无落盘方案就改业务代码
- ❌ 改完代码未更新静态真相文档，或绕开 `godkey_gate.py archive` 手动移动目录
- ❌ 只口头宣称“文档已同步”，未展示门禁脚本实际执行输出
