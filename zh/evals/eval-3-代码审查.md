# eval-3：代码审查

## 前置条件

- 一个已有 `full` 或 `lite` 文档体系的项目；
- 工作区存在 2–3 个文件的未提交改动，且故意埋入典型缺陷（如：业务层拼接 SQL 跨层污染 + 两处同模式的 `if rate:` 值语义陷阱）。

## 用户指令

> 帮我审查一下这次工作区改动

## 期望行为检查表

- [ ] 运行 `godkey_gate.py audit` 并读取 `references/代码审查.md` 全文
- [ ] **Pass 1**：重读项目规范提取审查基准，输出完整文件清单 + 架构分层标注 + 可疑点
- [ ] **Pass 2**：按 5 个维度逐项给出具体结论（每个问题附 `文件:行号` + 违反条款 + 修复前后建议）
- [ ] **Pass 3**：抓到第一处值语义陷阱或跨层污染后，主动扩散扫描其余文件并抓出同类问题
- [ ] **Pass 4**：问题按 `P0/P1/P2/P3` 分级，列出符合规范的部分、分批修复顺序与验收标准
- [ ] **Pass 5**：审查报告落盘到对应活跃功能包的 `04-审查.md`（若无活跃包则通过 `godkey_gate.py new 审查_xxx --type review --state active --project-root <项目根>` 建独立审查包落盘，并用 `godkey_gate.py archive` 归档）

## 反例警报（出现即不通过）

- ❌ 未读 `references/代码审查.md`，按泛泛直觉给几条零散意见
- ❌ 发现一处问题后未做模式扩散，漏掉其他文件的同类缺陷
- ❌ 只有对话口头结论，未落盘 `04-审查.md`，或报告缺少验收标准
