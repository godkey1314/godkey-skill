# eval-6：动态资产归宿、状态搁置与静态文档门禁

## 前置条件

- 一个 `full` 模式 Git 仓库，含基础业务代码与 `05-数据库/表结构快照.md`、`05-数据库/init_tables.sql`。

## 用户指令（分三步连续测试）

1. > 开始做“订单加优惠券字段”功能，先加一条迁移 SQL 并改下单逻辑；做到一半先暂停搁置，写明原因“等产品确认满减规则”。
2. > 恢复“订单加优惠券字段”继续做完，但假设我忘了提醒你更新数据库快照和功能设计文档，直接准备归档。
3. > 按门禁报错补齐静态真相文档后再完成归档。

## 期望行为检查表

- [ ] 第一步：用 `godkey_gate.py new` 建包，**把迁移 SQL 放入功能包的 `ops/`**（而不是乱放进 `05-数据库/` 或源码目录）；暂停时运行 `godkey_gate.py move <包> paused --reason "等产品确认满减规则"`，文件夹物理迁入 `03-已搁置/`
- [ ] 第二步：恢复时运行 `godkey_gate.py move <包> active` 迁回 `02-进行中/`；未同步静态文档时运行 `godkey_gate.py archive` 被门禁明确拦截（报 `featureDocs` 与 `dbDocs` 未同步，返回非零退出码）
- [ ] 第三步：AI 实际更新 `04-功能设计/` 与 `05-数据库/表结构快照.md`、`init_tables.sql`（仅存最新快照，过程迁移 SQL 仍留在功能包 `ops/`），重跑 `godkey_gate.py archive` 返回 `ARCHIVE PASS`，整个功能包迁入 `99-已归档/`

## 反例警报（出现即不通过）

- ❌ 把迁移 SQL 直接堆进静态 `05-数据库/` 或业务源码目录
- ❌ 只在 Markdown 正文里手写“状态：已搁置 / 已归档”，未用脚本移动文件夹
- ❌ 在静态文档确实变更的情况下，靠写空洞的 `doc-sync-waiver` 试图绕过门禁
