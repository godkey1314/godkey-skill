# eval-3：代码审查

## 前置条件

- 同 eval-1 的项目
- 工作区有一批未提交的改动（可以先用 AI 或手工改出 2-3 个文件，埋一个典型的跨层污染，如业务层拼 SQL）

## 用户指令

> 审查一下我这次改动

## 期望行为检查表

- [ ] 触发 godkey-skill，前置关卡快速通过（文档完整）
- [ ] **Read 了 `references/代码审查.md`**（核心验证点）
- [ ] Pass 1：先重读 `06-开发规范/` 提取审查基准，输出文件清单 + 分层标注
- [ ] Pass 2：按 5 个维度逐项检查，每个发现给出文件、位置、违反的具体条款（不是笼统"没问题"）
- [ ] Pass 3：发现问题模式后向其他文件扩散追查（如发现一处 N+1，去全局找同样的模式）
- [ ] Pass 4：问题按 P0-P3 分级，报告含修复顺序和验收标准
- [ ] Pass 5：报告落盘到 `10-开发方案/YYYY-MM-DD/`，文件名含"审查"标识

## 反例警报（出现即不通过）

- ❌ 没有 Read `references/代码审查.md`，按自己默认的审查习惯干活
- ❌ 只输出对话内的口头结论，报告不落盘
- ❌ 笼统说"整体质量不错，没有大问题"而不逐维度给结论
