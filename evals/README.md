# Evals：godkey-skill 行为验证集

## 为什么需要

本 skill 的核心设计是**渐进披露**：SKILL.md 只保留关卡判定标准，执行细节在 `references/` 子流程文档里。这个设计成立的前提是 AI 收到任务后**真的会去读子流程文档**——不读就开工，等于跳过了全部执行细节。

本目录用可复现的场景验证这件事，不靠感觉判断优化效果。

## 怎么跑

1. 开一个**全新会话**（干净上下文，没有历史残留）
2. 准备好场景要求的测试项目（每个 eval 文件里写了前置条件）
3. 把 eval 文件里的「用户指令」原话发给 AI
4. 观察它的**工具调用序列**（不是只看它说什么），对照该 eval 的检查表逐条打勾

## 判定标准

- **通过**：检查表全部命中，且没有触发任何「反例警报」
- **不通过**：任一反例警报触发（尤其是"没有 Read 任何 references/ 文件就开始改代码"——这是最核心的失败模式）
- 建议每个场景跑 3 次（不同会话），3 次全过才算稳定通过
