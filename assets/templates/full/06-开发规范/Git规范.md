# Git 协作规范

> 静态真相快照：定义本项目的分支模型、提交规范与安全红线。

## 1. 分支与版本约定

- `main` / `master`：稳定主干分支，保持随时可发布状态；版本封版使用附注标签（如 `v1.0.0`）。
- `dev/<主题>` 或 `feat/<功能名>`：新功能或大版本重构分支。
- `fix/<问题名>` / `hotfix/<问题名>`：缺陷修复分支。

## 2. Commit Message 格式

```text
<type>(<scope>): <subject>

<可选正文：说明动机与关键改动>
```

| Type | 说明 |
|------|------|
| `feat` | 新功能 |
| `fix` | Bug 修复 |
| `docs` | 文档更新（静态蓝图、功能包、模板等） |
| `refactor` | 重构（不改变外部行为） |
| `test` | 测试新增或调整 |
| `perf` | 性能优化 |
| `chore` | 构建、依赖、脚本与工具维护 |

## 3. 安全与提交前红线

- 禁止提交 `.env`、私钥、令牌、账密等敏感信息（仓库只保留 `.env.example`）；
- 禁止对共享主干分支执行 `git push --force` 或 `git reset --hard`；
- 禁止提交大段调试日志（`print`/`console.log`）或无意义注释代码；
- 如启用 `godkey_gate.py install-hook`，提交前会自动校验代码与文档同步状态。
