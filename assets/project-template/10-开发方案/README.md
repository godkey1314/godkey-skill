# 10-开发方案

> 按日期组织的开发方案文档。每次需要制定开发方案、重构方案、修复方案时，在此创建对应的方案文档。

---

## 目录结构

```
10-开发方案/
├── README.md
├── YYYY-MM-DD/              # 目录只用日期，不加序号
│   └── NN_方案名称.md      # 文件名加 2 位序号前缀
├── 2026-05-17/
│   ├── 01_用户模块优化方案.md
│   └── 02_支付接口加固方案.md
└── 2026-05-18/
    └── 01_数据同步重构方案.md      # 当天只有一个也带 01
```

## 命名规则

**目录 = 日期，序号放文件名。** AI 无需判断当天有几个方案，统一按 `NN_名称` 落盘即可。

| 对象 | 规则 | 示例 |
|------|------|------|
| 目录 | `YYYY-MM-DD`（只用日期，不加 `_序号` 后缀） | `2026-05-17` |
| 文件 | `NN_方案名称.md`（2 位数字序号前缀，从 `01` 起） | `01_用户模块优化方案.md`、`02_支付接口加固方案.md` |

- 当天第一个方案 → `01_名称.md`；第二个 → `02_名称.md`，依此类推
- **即使当天只有一个方案，文件名也带 `01`**——单/多方案同一套规则，不制造分支判断
- 同一目录下序号接续，不重复、不留空

## 文件命名

文件名采用 `NN_描述性中文名称`，名称直接反映方案内容。例如：

- `01_数据质量监控体系重构方案.md`
- `02_用户模块性能优化方案.md`
- `03_支付接口安全加固方案.md`

## 典型使用场景

- 新功能开发前：编写设计方案
- 重构前：编写重构方案
- 代码审查后：编写修复方案
- 架构调整：编写调整方案

## AI 使用说明

1. 需要制定开发方案时，按当前日期创建目录（只用日期，如 `2026-05-17/`，不要加 `_01` 后缀）
2. 文件名取 `NN_方案名称.md`，序号按当天已有方案数接续，当天第一个用 `01`
3. 参考项目已有文档（03-系统架构、04-功能设计）编写方案
4. 方案完成后，在 `09-AI开发日志` 中记录本次方案
