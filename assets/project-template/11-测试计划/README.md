# 11-测试计划

> 按日期组织的测试计划文档。每次需要编写测试（>3 用例或涉及集成/端到端测试）时，在此创建对应的测试计划文档。

## 目录结构

```
11-测试计划/
├── README.md
├── 测试计划模板.md            # 测试计划模板，创建测试计划时参考
├── YYYY-MM-DD/              # 目录只用日期，不加序号
│   └── NN_测试计划_功能名.md  # 文件名加 2 位序号前缀
├── 2026-05-17/
│   ├── 01_测试计划_用户登录模块.md
│   └── 02_测试计划_支付回调接口.md
└── 2026-05-18/
    └── 01_测试计划_数据同步模块.md      # 当天只有一个也带 01
```

## 命名规则

**目录 = 日期，序号放文件名。** AI 无需判断当天有几个测试计划，统一按 `NN_名称` 落盘即可。

| 对象 | 规则 | 示例 |
|------|------|------|
| 目录 | `YYYY-MM-DD`（只用日期，不加 `_序号` 后缀） | `2026-05-17` |
| 文件 | `NN_测试计划_功能名.md`（2 位数字序号前缀，从 `01` 起） | `01_测试计划_用户登录模块.md`、`02_测试计划_支付回调接口.md` |

- 当天第一个测试计划 → `01_测试计划_名称.md`；第二个 → `02_测试计划_名称.md`，依此类推
- **即使当天只有一个测试计划，文件名也带 `01`**——单/多计划同一套规则，不制造分支判断
- 同一目录下序号接续，不重复、不留空

## 文件命名

测试计划文件命名格式：`NN_测试计划_功能名.md`。例如：

- `01_测试计划_用户登录模块.md`
- `02_测试计划_支付回调接口.md`

## 典型使用场景

- 新功能开发完成后：编写该功能的测试计划
- Bug 修复后：编写回归测试计划
- 集成/端到端测试前：编写测试计划
- 小改动（≤3 用例、纯函数）可跳过，直接在日志中简述测试策略

## AI 使用说明

1. 需要制定测试计划时，参考 `测试计划模板.md` 创建文档
2. 按当前日期创建目录（只用日期，如 `2026-05-17/`，不要加 `_01` 后缀）
3. 文件名取 `NN_测试计划_功能名.md`，序号按当天已有测试计划数接续，当天第一个用 `01`
4. 测试完成后，在 `09-AI开发日志` 中记录，测试报告与测试计划放在同一目录
