# 测试流程

适用场景：编写测试、运行测试、验证功能与回归保护。

> **何时加载本文档**：独立测试任务，或 [开发流程](开发流程.md) Pass 4 需要编写/执行验证时。测试分级、真实链路要求、受限环境降级规则与报告格式只在本文档定义。

---

## 全局锁：按 Pass 0 → Pass 5 顺序执行。

---

## Pass 0：测试计划（先定策略，再写用例）

1. **标准功能包改动**：在功能包的 **`03-测试.md`** 第一节写清「纳入范围 / 不纳入范围与原因 / 测试环境与数据隔离 / 核心用例概要」，落盘后再写测试代码。
2. **Hotfix 单文件小修**：无需单建计划文档，直接先写能复现 Bug 的最小用例，验证结果记入 `hotfix记录.md`。
3. **`external` 模式**：先在对话中给出简明测试计划（范围、级别、边界用例），再编写执行。

---

## Pass 1：确定测试范围与最低要求

对照本次改动的影响面与项目测试规范，按改动类型套用最低要求：

| 改动类型 | 最低测试要求 |
|---|---|
| 新增 / 修改数据层查询 | 至少一条集成测试验证真实 SQL/存储行为 |
| 新增 / 修改业务编排 | 覆盖正常路径 + 关键错误分支 + 事务/副作用 |
| 新增 / 修改对外接口 | 验证状态码、响应结构、鉴权与异常入参 |
| 阈值 / 边界 / 数值计算 | 覆盖零值、空值、不足、刚好达标、超限 |
| 修复 Bug | **先写能复现原 Bug 的失败测试**，修复后再跑通确认 |
| 配置 / 脚本 / 门禁工具 | 在隔离临时目录跑端到端执行验证 |

明确列出**本次不测什么及原因**（已有覆盖 / 环境受限 / 不适用）。

---

## Pass 2：编写测试（真实链路优先 + 显式受限降级）

### 1. 默认铁律：验证真实链路
纯函数单测只是起点，**不得通过 mock 核心依赖来假装全链路已通过**：

| 链路 | 默认要求 |
|---|---|
| 数据库查询 | 使用测试库 / 临时库（如独立测试 DB、内存/临时 SQLite、测试容器），不 mock SQL 执行 |
| 业务编排 | 注入真实协作组件，验证完整调用链与状态变化 |
| 后台 / 定时任务 | 实际触发执行，验证数据落盘与幂等副作用 |
| HTTP / CLI 接口 | 发真实请求或子进程调用，验证退出码、状态码与输出 |

### 2. 受限环境显式降级规则（杜绝死卡，也杜绝静默作弊）
当运行环境**客观上无法访问外部依赖**（如无数据库沙箱、无第三方付费 API 测试账号、无 GPU/外部网络）：
1. 允许对**该外部边界**使用受控替身（Fake / Stub / 录制夹具）验证协议契约、参数组装与异常处理；
2. **必须在 `03-测试.md` 的链路结果表和「未覆盖项」中显式标明**：`受限降级（原因：xxx；已验证边界：xxx；待在测试环境补跑真实链路）`；
3. 严禁把降级测试写成“全链路已验证通过”。

### 3. 编写关注点
- **文件组织**：遵循项目现有测试目录结构与命名范式（无既有范式时默认按 `tests/<module>/test_<feature>.<ext>` 与源码一一对应）；
- **边界优先**：覆盖空值、`0`、空集合、超长/极限值、超时与并发竞争；
- **数据隔离**：绝不污染生产环境，测试完毕自动清理临时数据。

---

## Pass 3：运行与根因排查

1. 运行**新增测试 + 全部相关回归测试**，确认未破坏已有功能。
2. 遇到失败：**严禁注释、`skip` 或放宽断言敷衍通过**，必须先查清根因：
   - 业务代码 Bug → 修业务代码；
   - 测试用例假设错误 → 修测试；
   - 环境/夹具问题 → 修复测试环境并记录。

---

## Pass 4：覆盖检查与补漏

对照 Pass 1 清单逐条反查：
1. 每个直接改动点是否都有对应验证？
2. 关键链路与核心错误路径是否至少走通一遍？
3. 零值、空值与阈值边界是否已覆盖？
4. 是否存在未经显式说明就 mock 掉核心依赖的情况？

发现漏测 → 回到 Pass 2 补齐并重跑 Pass 3。

---

## Pass 5：测试报告落盘

将实测命令、通过/总计数量、链路验证表（含受限降级说明）与未覆盖项写入：
- **`full` / `lite` 功能包**：写入功能包的 **`03-测试.md`** 第二节「测试报告」；
- **Hotfix**：通过 `godkey_gate.py hotfix --verify "..."` 记入 `hotfix记录.md`；
- **`external` 模式**：在回复中输出完整测试报告（含实际执行的命令与真实输出摘要）。

禁止只口头说“测试过了”而不给出执行命令与真实结果。
